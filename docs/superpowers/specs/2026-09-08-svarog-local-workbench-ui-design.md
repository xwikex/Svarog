# Svarog 本地可视化工作台设计

日期：2026-09-08

状态：用户已确认，可进入实施

目标平台：Windows 与 Linux，首轮由用户在 Windows 虚拟机验收

## 1. 目标

在现有 Svarog 命令行功能之上增加浅色本地网页工作台。工作台覆盖现有 Web 日志分析、SOP 告警调查、案件历史、Python 环境漏洞审计、项目锁文件审计和 Doctor 检查。CLI 保持兼容，网页层复用现有 Python 业务函数，不复制审计逻辑。

用户通过 `svarog ui` 启动服务，然后在 Windows 虚拟机浏览器中操作。服务默认仅监听 `127.0.0.1`，不自动开放局域网，不提供自动处置能力。

## 2. 明确不做

- 不实现实时日志采集、后台监听、SIEM/EDR 连接器或 WebSocket 推送。
- 不实现多人账户、登录、RBAC、数字签名或远程协作。
- 不执行封禁 IP、修改防火墙、停止进程、写业务系统或运行 Shell 命令。
- 不扩展 Doctor 已锁定的检查范围。
- 不自动发现 Windows Python 环境、锁文件或数据库。
- 不将模型输出视为事实，不让模型决定文件、查询范围或复核状态。
- 不引入 Node.js、React/Vue 构建链或外部 CDN。

## 3. 技术方案

### 3.1 服务端

新增轻量本地 Web 模块和 `svarog ui` 命令。使用 Python 内置 HTTP 能力提供页面、静态资源和表单/API 请求，避免新增运行依赖。若实现阶段证明标准库无法在合理代码量内提供清晰可靠的请求边界，应先回到设计评审，而不是静默引入框架。

启动参数：

```text
svarog ui --host 127.0.0.1 --port 8765 --workspace <目录> --case-db <文件>
```

- `--host` 第一版只接受回环地址 `127.0.0.1`、`localhost` 或 `::1`。
- `--port` 接受 1..65535；端口占用时给出中文错误并退出。
- `--workspace` 是页面可引用的路径边界，必须显式提供且为现有可读目录。
- `--case-db` 是独立 SOP 案件库；默认位于工作区的 `.svarog/cases.sqlite3`。不得与漏洞库、输入文件或报告文件重合。
- 不默认自动打开浏览器。提供 `--open-browser` 可选参数，用户主动传入时才打开；本轮物理机验收禁止使用该参数。

### 3.2 前端

前端使用打包在 Python 包中的原生 HTML、CSS 和少量 JavaScript。全部资源由本地服务提供，不引用外部字体、图标、脚本、图片或分析服务。

- 服务端生成初始页面和数据；JavaScript只负责页面切换、表单提交、加载状态、筛选和局部刷新。
- 所有不可信文字使用文本节点或服务端转义，不拼接到可执行 HTML。
- 浏览器端不保存 Token、模型密钥或完整案件副本到 localStorage/sessionStorage。
- 图标使用随包提供的 SVG，并包含可访问名称；不使用 emoji 作为功能图标。

### 3.3 业务适配层

新增独立适配层，把网页请求转换成现有服务函数调用：

- SOP：复用 `svarog.sop.service.run_case`、`CaseStore` 和报告写入逻辑。
- Web 日志分析：复用 `parse_jsonl`、`build_report` 和报告渲染逻辑。
- Python 环境审计：复用 `dependency_audit` 的 inventory、repository 和 service。
- 项目审计：复用 `project_audit` 的 lockfile、reconcile、service 和 reporting。
- Doctor：复用当前范围锁定的 `run_doctor`。

适配层负责请求校验、临时文件生命周期、路径授权、错误翻译和响应序列化，不负责重新实现检测规则。

## 4. 信息架构与页面

采用浅色桌面工作台：左侧导航、顶部运行状态栏和主内容区。主要为 Windows 桌面浏览器设计，同时保证窄屏下无横向页面滚动。

### 4.1 概览

- 案件总数、待确认数量和最近案件。
- 最近一次 Python/项目审计结果摘要，仅显示当前进程会话中的运行记录；第一版不新增通用审计历史表。
- 最近一次 Doctor 状态；未运行时明确显示“尚未检查”。
- 快捷入口：新建 SOP 调查、项目审计、环境审计、Doctor。

### 4.2 新建 SOP 调查

三段式表单：

1. 选择告警 JSON、日志文件和日志格式。
2. 设置时间窗口、保留上限、Nginx 日志主机和可选模型配置。
3. 检查摘要并提交。

分析期间显示当前阶段，不显示虚假的百分比。完成后跳转案件详情；失败时保留非敏感表单选择，错误显示在相关字段旁。

### 4.3 案件详情

- 顶部：告警标题、严重度、案件状态、七步 SOP 进度和“未执行处置”。
- 标签页：证据、IOC、ATT&CK 候选、处置建议、人工确认。
- 证据、IOC、映射和建议通过 evidence ID 互相跳转。
- 人工确认要求决定、姓名、备注。按钮使用“记录批准意见”“记录拒绝意见”“要求补充调查”，不用“执行处置”等误导用语。
- 复核后不可覆盖；需要新结论时重新创建案件。
- 提供 JSON/单文件 HTML 下载；下载响应不在服务器任意路径写文件。

### 4.4 案件历史

- 读取独立 SQLite 案件库。
- 按状态筛选，按案件 ID、告警 ID、标题进行本地关键词搜索。
- 默认按创建时间倒序，分页读取，不一次解压/解析全部历史载荷。
- 第一版不提供删除、合并、批量复核或数据迁移按钮。

为支持列表查询，案件库迁移增加必要摘要列或索引。迁移沿用 `PRAGMA application_id` 与 `user_version` 保护，不接管未知数据库。旧 v1 案件库必须可安全升级并保持案件、复核记录和原始 JSON 不变。

### 4.5 Web 日志分析

- 上传一个 JSONL 文件，调用现有本地检测规则。
- 页面显示总事件、可疑事件、输入问题、严重度分布和证据列表。
- 支持直接下载 JSON 报告，不覆盖上传文件。

### 4.6 Python 环境审计

- 明确填写 Python 环境目录。
- 漏洞来源二选一：工作区内只读 SQLite，或显式远程 API 地址。
- Token 只读取服务器环境变量；页面仅显示“已配置/未配置”。
- 结果显示包清单、匹配漏洞、状态和警告，并支持 JSON 下载。

### 4.7 项目审计

- 明确填写 Python 环境路径和 `poetry.lock` / `uv.lock` 路径。
- 显示锁文件依赖、环境依赖、版本差异和漏洞结果。
- 支持 JSON 与无外部依赖 HTML 下载。
- 不扩大到 requirements.txt、pyproject.toml 或自动 `.venv` 发现。

### 4.8 Doctor

界面仍只表达三组检查：

1. Python 环境与包管理工具是否可用。
2. 核心数据源 SQLite 或远程 API 是否就绪。
3. 核心目录与网络权限是否具备。

不显示 CPU、内存、完整 PATH 或网络测速。

### 4.9 设置

第一版不建立持久化设置数据库。页面可以在当前浏览器会话中保留非敏感表单偏好，但服务端仍以启动参数为权限边界。密钥、Token 和认证信息不得进入浏览器存储。

## 5. 视觉系统

整体为内容优先的浅色安全工作台，追求清楚、克制和可信，不模拟电影式“黑客屏幕”。

- 页面背景：冷白/浅灰；容器：白色；正文：深蓝灰。
- 主色：青绿色，用于导航、主按钮和正常完成状态。
- 风险色：橙色表示提醒，红色表示高风险或失败；颜色之外同时使用文字与图标表达状态。
- 字体：操作系统无衬线字体栈，正文不小于 14px，默认 16px，行高至少 1.5。
- 表单控件和按钮最小高度 44px；键盘焦点清晰可见。
- 内容宽度自适应，桌面使用信息密度适中的卡片和表格；小屏将双栏变单栏。
- 动效仅用于 150–250ms 的加载、标签切换和提示出现，并遵循 `prefers-reduced-motion`。
- 页面顶部固定展示“本地只读分析 / 未执行处置”状态，避免误解产品权限。

## 6. 请求与数据流

### 6.1 启动

CLI 校验回环地址、端口、工作区和案件库，然后初始化数据库迁移，生成进程级 CSRF 密钥并启动本地服务。任何一项失败都在终端给出安全的中文错误并退出。

### 6.2 文件上传

浏览器上传告警和日志副本时：

1. 服务先检查 Content-Length、Content-Type、文件数和每个文件大小。
2. 数据流写入工作区内专用临时目录，文件名由服务生成，不使用客户端文件名作为路径。
3. 拒绝符号链接、设备文件、路径穿越和不允许的扩展/格式。
4. 调用现有解析与分析服务。
5. 关闭所有句柄后清理临时文件；清理失败写入本机终端警告。

SOP 首版告警最大 64 KiB、日志最大 10 MiB，沿用已有限制。Web 日志分析也沿用现有 10 MiB 与单行 1 MiB 限制。

### 6.3 路径型输入

Python 环境、锁文件和漏洞库可能较大，不通过浏览器上传。用户输入相对于启动工作区的路径，服务进行规范化并验证最终目标位于工作区内。默认拒绝绝对路径、`..`、符号链接逃逸和工作区外目标。

目录必须符合对应现有函数的类型要求。所有输入保持只读。服务端报告下载优先流式返回；如果未来增加服务器端落盘，必须显式选择工作区内报告目录并复用原子写入和别名检查。

### 6.4 结果与案件

- 普通 Web/Python/项目/Doctor 结果存放于当前服务进程的有界运行记录缓存，服务重启后清空。
- SOP 结果写入独立案件 SQLite，并从该库读取历史与复核状态。
- JSON 是事实源；页面和 HTML 是渲染视图。
- 浏览器刷新案件详情时重新读取数据库，避免旧页面伪装成最新状态。

## 7. Web 安全边界

- 服务只绑定回环地址，并检查 Host 与请求来源；第一版不支持反向代理或远程部署。
- 所有状态修改请求使用不可预测、进程级 CSRF Token，并验证同源 Origin/Referer；Token 不写日志。
- 响应包含严格 CSP、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、`Cache-Control: no-store` 和禁止嵌入策略。
- 会话 cookie 如需使用，必须为 `HttpOnly`、`SameSite=Strict`；本设计优先采用无身份会话的 CSRF Token，不存储敏感状态。
- 路由只暴露固定操作，不接受模块名、函数名、Shell 参数或任意 SQL。
- SQL 全部参数化；案件列表使用固定列、固定排序和分页上限。
- 错误响应不包含栈、密钥、完整绝对路径或远程响应正文；详细诊断只写本机终端并做敏感字段过滤。
- 可选模型沿用现有显式配置、HTTPS/回环 HTTP、禁止重定向、无系统代理、上下文/响应大小限制和本地降级策略。
- 网页中的“批准”只写复核表；后端不存在对应的自动处置执行器。

## 8. 错误与运行状态

- 页面采用统一结构：错误代码、面向用户的中文说明、建议下一步。
- 字段错误紧邻输入显示；全局错误只用于服务不可用或数据库不兼容。
- 长操作显示当前阶段和开始时间；第一版不实现取消，不承诺精确进度。
- 若 SOP 案件已保存但报告渲染失败，显示案件 ID，并允许在详情页重新下载。
- 模型失败显示“已降级为本地规则”，不会把降级描述为模型完成。
- 无匹配日志显示“证据不足”，不会显示“安全”或“误报”。

## 9. 测试与验收

### 9.1 自动化测试

- CLI：`svarog ui --help`、默认参数、非法主机/端口/工作区、端口占用。
- HTTP：页面路由、方法限制、404、请求体上限、安全响应头和内容类型。
- 表单：必填、枚举、长度、文件数量、上传截断、CSRF、Origin/Host。
- 路径：`..`、绝对路径、符号链接逃逸、硬链接/输入输出别名和工作区外目标。
- 业务：SOP 全流程、案件历史/分页/筛选/复核、Web 分析、Python 审计、项目审计、Doctor。
- 呈现：HTML/JSON 注入、控制字符、空结果、坏行、截断、模型降级。
- 兼容：原有 CLI 测试全部继续通过；新 Web 测试不依赖网络或浏览器。

### 9.2 构建与安装

- 构建 wheel，安装到隔离目录，验证模板/样式/脚本随包分发。
- 在隔离安装中运行 HTTP 处理器级冒烟测试。
- 本轮在物理机不启动服务、不打开浏览器。

### 9.3 Windows 虚拟机人工验收

交付独立文档，从复制项目文件夹、重新创建 `.venv` 开始，包含：

- 启动工作台并手动打开本地 URL。
- 使用合成样例跑 SOP、保存人工复核、重新查看案件。
- 跑 Web 日志分析、Doctor、Python 环境审计和项目锁文件审计。
- 验证刷新、下载、错误提示、窄屏布局和服务停止。
- 验证未配置模型时无外网请求，任何复核决定都不执行处置。

## 10. 完成标准

以下条件全部满足才算第一版完成：

1. 概览和六个功能页面可从统一导航访问，并调用现有业务逻辑。
2. SOP 可以创建案件、展示完整证据链、记录一次人工复核并从历史中重新打开。
3. Python/项目审计和 Doctor 能通过受限路径表单运行。
4. 所有报告可下载，不覆盖输入或数据库。
5. 页面不使用外部资源，浅色、响应式、键盘可操作，风险不只依赖颜色表达。
6. 回环绑定、CSRF、请求大小、路径边界、转义、安全响应头有自动化测试。
7. 原有测试与新增测试通过；平台特定跳过必须明确说明原因。
8. wheel 安装后静态资源完整。
9. 提供 Windows 虚拟机部署与逐功能验收说明。
10. 当前物理机不启动服务或打开页面；视觉人工验收明确留给 Windows 虚拟机。
